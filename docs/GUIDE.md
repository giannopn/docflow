## Τελική εργασία στο μάθημα Τεχνολογία Πολυμέσων

# Περιγραφή Εφαρμογής

Στα πλαίσια της εργασίας θα υλοποιηθεί ένα απλό σύστημα διαχείρισης εγγράφων. Η
εφαρμογή θα υποστηρίζει διαφορετικές κατηγορίες χρηστών με συγκεκριμένα
δικαιώματα χρήσης.

# Α.1. Σχεδιασμός και υλοποίηση λογικής ( 40 %)

Η εφαρμογή θα πρέπει να υποστηρίζει τις ακόλουθες κατηγορίες χρηστών.

**Απλός Χρήστης:** Ο απλός χρήστης θα έχει πρόσβαση σε όλα τα έγγραφα που ανήκουν
στις κατηγορίες που του έχουν ανατεθεί από τον διαχειριστή κατά την εγγραφή του στο
σύστημα. Ο απλός χρήστης θα μπορεί μόνο να διαβάσει τα σχετικά έγγραφα, δηλαδή να
έχει πρόσβαση στον τίτλο του εγγράφου, στο όνομα του συγγραφέα, στην ημερομηνία
δημιουργίας, στο περιεχόμενο, και τον αριθμό έκδοσης (versioning number). Ο απλός
χρήστης στα έγγραφα που έχει πρόσβαση θα βλέπει μόνο την τελευταία έκδοση.
Επιπλέον, θα μπορεί να επιλέξει να παρακολουθεί όσα έγγραφα επιθυμεί. Αυτό σημαίνει
ότι αν ένα έγγραφο τροποποιηθεί (αλλάξει ο αριθμός έκδοσης), στην επόμενη είσοδο
του χρήστη στο σύστημα θα πρέπει να ενημερωθεί για την ύπαρξη νέας έκδοσης.
Αντίστοιχα, θα μπορεί να αφαιρέσει την παρακολούθηση εγγράφων. Τέλος, θα μπορεί
να αναζητά έγγραφα με βάση την κατηγορία, το όνομα του εγγράφου και του
συγγραφέα.

**Συγγραφέας:** Ο συγγραφέας έχει όλα τα **δικαιώματα και τις λειτουργίες** των απλών
χρηστών σε συνδυασμό με την δυνατότητα δημιουργίας και διαχείρισης εγγράφων.

Προσθήκη, τροποποίηση, και διαγραφή εγγράφων

Ο συγγραφέας θα μπορεί να δημιουργεί, τροποποιεί, και διαγράφει έγγραφα σε όποια
κατηγορία έχει δικαίωμα πρόσβασης από τον διαχειριστή. Κάθε έγγραφο έχει ως
υποχρεωτικά πεδία: τίτλο, όνομα συγγραφέα, κατηγορία, ημερομηνία δημιουργίας, και
φυσικά το κυρίως κείμενο του εγγράφου. Για λόγους απλότητας, τα έγγραφα θα
περιλαμβάνουν μόνο κείμενο και η μόνη μορφοποίηση που ζητείται να υλοποιηθεί


απαραίτητα είναι η ύπαρξη παραγράφων. Ο προκαθορισμένος αριθμός έκδοσης για
κάθε νέο έγγραφο θα είναι 1.

Κατά την τροποποίηση ενός εγγράφου θα μπορεί να αλλάξει μόνο το κείμενο του
εγγράφου, χωρίς να μπορεί να γίνει αλλαγή στο όνομα ή την κατηγορία. Η διαδικασία
τροποποίησης θα πρέπει να υποστηρίζει versioning. Επομένως, όταν ένα έγγραφο
τροποποιηθεί θα δημιουργείται μια νέα έκδοση (με αυτόματη αύξηση κατά 1 του
αριθμού έκδοσης του εγγράφου) χωρίς όμως να διαγράφεται η παλιά έκδοση. Οι
χρήστες που ανήκουν στους συγγραφείς θα μπορούν εκτός από την τελευταία έκδοση
του κάθε εγγράφου να έχουν πρόσβαση και το πολύ στις δυο προηγούμενες εκδόσεις.

Στην περίπτωση διαγραφών θα αφαιρούνται πλήρως τα έγγραφα και όλες οι σχετικές
εκδόσεις ενώ θα πρέπει να φροντίσετε να γίνεται η κατάλληλη ενημέρωση των πιθανών
παρακολουθήσεων που έχουν οριστεί για τα προς διαγραφή έγγραφα.

**Διαχειριστής:** Ο διαχειριστής θα έχει όλα τα **δικαιώματα και τις λειτουργίες** των
συγγραφέων σε συνδυασμό με τις παρακάτω επιπλέον δυνατότητες.

Προσθήκη και διαγραφή χρήστη

Ο διαχειριστής θα μπορεί να προσθέτει και να διαγράφει χρήστες. Για την προσθήκη ενός
χρήστη θα πρέπει να οριστούν: α) όνομα και επώνυμο, b) κατηγορία χρήστη, c)
τουλάχιστον μια κατηγορία εγγράφων που θα μπορεί να έχει πρόσβαση, d) username
και password. Η υλοποίηση θα πρέπει να υποστηρίζει ένα προεπιλεγμένο διαχειριστή με
username _“medialab”_ και password _“medialab_2025”_.

Προσθήκη, τροποποίηση, και διαγραφή κατηγορίας εγγράφων

Ο διαχειριστής θα μπορεί να ορίζει νέες κατηγορίες, δίνοντας το σχετικό όνομα.
Επιπλέον, θα μπορεί να τροποποιήσει τον όνομα μιας κατηγορίας. Για λόγους απλότητας
θεωρούμε ότι δεν υπάρχουν υποκατηγορίες. Επίσης, θα μπορεί να διαγράφει μια
κατηγορία μαζί με την αυτόματη διαγραφή όλων των εγγράφων που ανήκουν σε αυτή.
Σε αυτή την περίπτωση θα πρέπει να γίνεται η κατάλληλη ενημέρωση των
παρακολουθήσεων για τα έγγραφα που διαγράφονται.

# Α. 2. Αποθήκευση και ανάκτηση πληροφοριών εφαρμογής ( 10 %)

Για την αποθήκευση και ανάκτηση των πληροφοριών της εφαρμογής θα χρησιμοποιηθεί
μια λύση βασισμένη στη χρήση αρχείων που θα περιέχουν δεδομένα σε μορφή JSON.

Το JSON (JavaScript Object Notation) είναι μια μορφή αναπαράστασης δεδομένων που
χρησιμοποιείται ευρέως για την αποθήκευση και τη μεταφορά δεδομένων. Είναι εύκολο
στην ανάγνωση από ανθρώπους και, ταυτόχρονα, κατανοητό από αρκετές γλώσσες
προγραμματισμού. Το JSON ακολουθεί μια απλή δομή χρησιμοποιώντας κείμενο για να


αναπαραστήσει δεδομένα με μορφή κλειδιών-τιμών. Περισσότερες πληροφορίες
μπορείτε να βρείτε στις διαφάνειες του εργαστηρίου στην ενότητα _“Java Networking &
JSON”_.

Αρχικά θα πρέπει να ορίσετε την δική σας οργάνωση (data schema) για τα JSON
δεδομένα καθώς και το σύνολο των αρχείων που θα χρησιμοποιηθούν για την
αποθήκευση των δεδομένων της εφαρμογής. Τα αρχεία με τα δεδομένα της εφαρμογής
θα πρέπει να αποθηκεύονται σε ένα φάκελο με όνομα **_“medialab”._**

Στην συνέχεια πρέπει να υλοποιήσετε μέσω των κατάλληλων κλάσεων τις μεθόδους που
θα επιτρέπουν: (i) την ανάκτηση των πληροφοριών από τα αρχεία, (ii) την αρχικοποίηση
των κατάλληλων αντικειμένων στην εφαρμογή σας, και (iii) την ανανέωση των αρχείων
ώστε να διατηρείται η συνολική κατάσταση μεταξύ διαδιαχικών εκτελέσων.

Η υλοποίηση θα πρέπει να υποστηρίζει τις παρακάτω προδιαγραφές σχετικά με την
ανάκτηση και ανανέωση των δεδομένων της εφαρμογής.

- Αρχικοποίηση εφαρμογής: Θα πρέπει να γίνεται η ανάκτηση όλων των
  πληροφοριών που βρίσκονται στα JSON αρχεία και ταυτόχρονα η αρχικοποίηση
  των αντίστοιχων αντικειμένων στην εφαρμογή σας.
- Εκτέλεση εφαρμογής: Η εφαρμογή θα χρησιμοποιεί τις πληροφορίες κατάστασης
  που έχουν ανακτηθεί στην μνήμη του προγράμματος κατά την αρχικοποίση. Όλες
  οι λειτουργίες που σχετίζονται με την διαχείριση των εγγράφων θα εκτελούνται
  με βάση τις πληροφορίες που υπάρχουν στην μνήμη του προγράμματος.
- Τερματισμός εφαρμογής: Η ανανέωση των JSON αρχείων με τις πληροφορίες
  κατάστασης του συστήματος θα γίνεται αποκλειστικά πριν τον τερματισμό της
  εφαρμογής. Η υλοποίηση θα πρέπει να αποθηκεύει στα αντίστοιχα JSON αρχεία
  την συνολική κατάταση της εφαρμογης κατά την στιγμή του τερματισμού.

# A. 3. Δημιουργία γραφικής διεπαφής ( 30 %)

Θα πρέπει να σχεδιάσετε και να υλοποιήσετε την κατάλληλη γραφική διεπαφή χρήστη
(Graphical User Interface - GUI) χρησιμοποιώντας το πλαίσιο JavaFX [1][2].

**Σημείωση:** Στη συνέχεια παρουσιάζονται οι βασικές προδιαγραφές για την γραφική
διεπαφή, για όλες τις λεπτομέρειες της τελικής υλοποίησης μπορείτε να κάνετε όποιες
επιλογές θέλετε σχετικά με την εμφάνιση και τη γενικότερη αλληλεπίδραση του χρήστη
με την εφαρμογή, χωρίς καμία επίπτωση στην τελική βαθμολογία. Για παράδειγμα,
μπορείτε να επιλέξετε μια απλή απεικόνιση για τα διάφορα στοιχεία ή να συνδυάσετε
διάφορα χαρακτηριστικά από τo JavaFX ώστε να δημιουργήσετε ένα αποτέλεσμα που να
αντιστοιχεί σε μια σύγχρονη εφαρμογή. Σε κάθε περίπτωση, δεν υπάρχει λόγος να
κάνετε πολύπλοκο το συγκεκριμένο μέρος της εργασίας.


Αρχικά, κατά την εκκίνηση της εφαρμογής θα πρέπει να εμφανίζεται η κατάλληλη
διεπαφή που θα επιτρέπει στους χρήστες να συνδεθούν στο σύστημα με βάση τα
στοιχεία του λογαριασμού τους που έχουν οριστεί από τον διαχειριστή. Μετά την
επιτυχή σύνδεση, αν υπάρχουν έγγραφα που παρακολουθεί ο χρήστης και έχουν
ανανεωθεί θα πρέπει να ενημερώνεται σχετικά με ένα κατάλληλο popup παράθυρο.

Σχετικά με την δημιουργία της κυρίως γραφικής διεπαφής θα πρέπει να ακολουθήσετε
τις παρακάτω γενικές οδηγίες:

- Δημιουργήστε το κεντρικό «παράθυρο» της εφαρμογής με τίτλο “MediaLab
  Documents” και ορίστε τις κατάλληλες διαστάσεις.
- Χωρίστε το παράθυρο σε δύο βασικά μέρη.
  o Στο ένα μέρος θα εμφανίζονται συγκεντρωτικές πληροφορίες που θα
  πρέπει να ανανεώνονται με βάση τις ενέργειες του χρήστη. Οι
  πληροφορίες θα περιλαμβάνουν: (i) τον συνολικό αριθμό κατηγοριών στο
  σύστημα, (ii) το συνολικό πλήθος διαφορετικών εγγράφων στο σύστημα,
  και (iii) τον αριθμό εγγράφων που παρακολουθεί ο χρήστης.
  o Στο άλλο μέρος θα υλοποιηθούν οι διάφορες λειτουργίες που πρέπει να
  υποστηρίζει η γραφική διεπαφή. Υπάρχει πλήρης ελευθερία για τον τρόπο
  υλοποίησης των συγκεκριμένων λειτουργιών, ωστόσο, θα πρέπει να
  φροντίσετε να γίνεται κατάλληλη ενημέρωση των πληροφοριών στην
  γραφική διεπαφή ανάλογα με τις ενέργειες του χρήστη.

Η γραφική διεπαφή θα πρέπει να υποστηρίζει τις παρακάτω λειτουργίες:

- Διαχείριση κατηγοριών: η εφαρμογή πρέπει να παρουσιάζει στους διαχειριστές
  την λίστα με τις κατηγορίες εγγράφων. Ο διαχειριστής θα μπορεί να ορίζει νέες
  κατηγορίες, να αλλάζει το όνομα μιας κατηγορίας και να διαγράφει κατηγορίες.
  Η υλοποίηση πρέπει να γίνει με βάση τις προδιαγραφές από την ενότητα Α.1.
- Διαχείριση χρηστών: η εφαρμογή πρέπει να παρουσιάζει στους διαχειριστές τους
  χρήστες του συστήματος. Επίσης, θα πρέπει να υπάρχει η δυνατότητα ο
  διαχειριστής να προσθέτει, τροποποιεί, και διαγράφει χρήστες. Η υλοποίηση
  πρέπει να γίνει σύμφωνα με τις αντίστοιχες προδιαγραφές από την ενότητα Α.1.
- Αναζήτηση εγγράφων: θα πρέπει να υπάρχει η αντίστοιχη φόρμα που θα
  επιτρέπει την αναζήτηση εγγράφων με βάση τις προδιαγραφές από την ενότητα
  Α.1. Τα αποτελέσματα θα πρέπει να περιλαμβάνουν: τίτλο, συγγραφέα,
  κατηγορία, ημερομηνία δημιουργίας, και αριθμό έκδοσης.
- Διαχείριση παρακολούθησης εγγράφων: η εφαρμογή πρέπει να παρουσιάζει
  όλες τις ενεργές παρακολουθήσεις εγγράφων ενός χρήστη. Ο χρήστης θα πρέπει
  να έχει την δυνατότητα να ορίζει νέες παρακολουθήσεις ή να αφαιρεί σύμφωνα
  με την αντίστοιχη λογική από την ενότητα Α.1.


- Διαχείριση εγγράφων: η εφαρμογή πρέπει να παρουσιάζει στους χρήστες τα
  διαθέσιμα έγγραφα ανά κατηγορία που έχουν δικαίωμα πρόσβασης. Αν
  πρόκειται για απλό χρήστη θα μπορεί να δει μόνο την τελευταία έκδοση ενός
  εγγράφου με βάση τις προδιαγραφές από την ενότητα Α1, διαφορετικά θα
  πρέπει να μπορεί να επιλέγει πια από τις διαθέσιμες εκδόσεις θα δει. Επιπλέον,
  στους συγγραφείς και διαχειριστές θα πρέπει να δίνεται η δυνατότητα να
  τροποποιούν ένα έγγραφο καθώς και να διαγράφουν.

Τέλος, θα πρέπει η υλοποίηση της γραφικής διεπαφής κατά τον τερματισμό της
εφαρμογής να εξασφαλίζει την ανανέωση των πληροφοριών του συστήματος στα
σχετικά αρχεία, σύμφωνα με την διαδικασία που περιγράφεται στην ενότητα Α.2.

# A.4. Λοιπές απαιτήσεις ( 20 %)

- Η υλοποίηση θα πρέπει να ακολουθεί τις αρχές σχεδίασης του
  αντικειμενοστραφούς προγραμματισμού (OOP design principles).
- Σε μια κλάση της επιλογής σας θα πρέπει κάθε public μέθοδος που περιέχει να
  είναι τεκμηριωμένη σύμφωνα με τις προδιαγραφές του εργαλείου javadoc [3].

**Σημείωση:** Για οτιδήποτε δεν είναι ξεκάθαρο από την εκφώνηση μπορείτε να κάνετε τις
δικές σας παραδοχές και υποθέσεις. Η εκφώνηση περιγράφει τις βασικές απαιτήσεις για
την εφαρμογή, ωστόσο μπορείτε να κάνετε δικές σας σχεδιαστικές παραδοχές
προσπαθώντας να κάνετε πιο ρεαλιστική την εφαρμογή, χωρίς παράλληλα να κάνετε
πολύπλοκη την υλοποίηση.

# Παραδοτέα

- Το project (του IDE της επιλογής σας) με τον κώδικα υλοποίησης της εφαρμογής.
- Μια σύντομη (το πολύ 3 σελίδες) αναφορά που θα περιέχει μια γενική περιγραφή
  του σχεδιασμό της υλοποίησης και την περιγραφή του σχεδιασμού σας σχετικά
  με την δομή της πληροφορίας στα διαφορετικά JSON αρχεία. Επίσης, θα
  αναφέρετε όποια λειτουργικότητα δεν έχετε υλοποιήσει καθώς και όποιες
  παραδοχές έχετε κάνει. Σε καμία περίπτωση δεν θα πρέπει να συμπεριλάβετε
  τμήματα κώδικα.
